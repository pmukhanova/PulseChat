# Сценарий демонстрационного видео

Цель: показать работающий PulseChat без ручного монтажа и без reload, 120–150 секунд, экран 1440×900. Основной файл — `artifacts/demo/pulse-chat-presentation-demo.webm`; фоновые действия второго пользователя проверяются вторым реальным браузерным контекстом.

## Последовательность

1. Регистрация временного пользователя и вход в PulseChat.
2. Создание исходного DIRECT с `maria`, чтобы новый чат от `andrey` оставался неактивным.
3. Во втором контексте `andrey` создаёт DIRECT с временным пользователем. В sidebar первого контекста появляется чат без reload.
4. `andrey` отправляет сообщение. У временного пользователя меняются preview и порядок sidebar, появляется локальный unread badge.
5. Временный пользователь открывает новый чат: сообщение отображается, badge очищается.
6. `andrey` создаёт GROUP с временным пользователем. В первом интерфейсе появляется новая группа; роль — MEMBER, административные действия отсутствуют.
7. `andrey` назначает `demo_user` ADMIN. Открытая группа обновляет роль и разрешённые элементы без reload.
8. `andrey` переименовывает группу в `Проектная группа`; новое название появляется у `demo_user` без reload.
9. `demo_user` как ADMIN добавляет `olga`; новый участник появляется у `andrey` без reload.
10. `andrey` добавляет `demo_user` в seed-группу `Команда Pulse`. Пользователь открывает её, показывает загрузку старых сообщений вверх и поиск `архитектура`.
11. `demo_user` возвращается в `Проектная группа`, после чего `andrey` удаляет его.
12. Удалённый участник получает `chat_access_revoked`, группа исчезает из sidebar, а повторный REST-доступ возвращает 403 — без `page.reload()`.

## Проверка результата

- видео открывается как VP8 WebM, содержит фактический UI, имеет разрешение 1440×900 и длится 125,08 секунды;
- в кадре видны регистрация/вход, новый DIRECT, preview/сортировка/unread, GROUP, смена роли, rename, add/remove member, `chat_access_revoked`, pagination и поиск;
- второй браузерный контекст действительно выполняет действия инициатора; assertions не допускают фиктивный ролик;
- в видео и тестовых артефактах нет секретов.

Команда и итоговый статус указываются в `docs/testing.md` после финального запуска.
