# Роли и права доступа PulseChat

## Модель ролей

Роль хранится не в `users`, а в строке `chat_members`. Поэтому один пользователь может быть OWNER в одной группе, ADMIN в другой и MEMBER в третьей.

В GROUP-чате используются три роли:

- `OWNER` - владелец и старший администратор группы. Создаёт группу, управляет администраторами и имеет максимальные права внутри неё.
- `ADMIN` - администратор с делегированными операционными правами: переименование, добавление участников и удаление обычных MEMBER.
- `MEMBER` - обычный участник: чтение, поиск и отправка сообщений без административных действий.

`OWNER` - именно старший администратор, а не просто «ещё один ADMIN»: только он назначает и снимает ADMIN, может удалить ADMIN и не может быть удалён в MVP.

В DIRECT-чате оба собеседника имеют техническую роль `MEMBER`, а название и состав через API неизменяемы.

## Матрица действие x роль

Обозначения: `Да` - разрешено при членстве в чате; `Нет` - сервер возвращает запрет или не предоставляет операцию; `GROUP` - действие имеет смысл только для группового чата.

| Действие | OWNER | ADMIN | MEMBER | Условие |
|---|:---:|:---:|:---:|---|
| Получить список своих чатов | Да | Да | Да | Возвращаются только чаты пользователя |
| Открыть свой чат и список участников | Да | Да | Да | Требуется членство |
| Читать историю | Да | Да | Да | Требуется членство |
| Искать сообщения внутри чата | Да | Да | Да | Требуется членство |
| Войти в Socket.IO room чата | Да | Да | Да | `join_chat` проверяет членство |
| Отправлять сообщения | Да | Да | Да | Требуется членство |
| Переименовать GROUP | Да | Да | Нет | Только GROUP |
| Добавить нового MEMBER | Да | Да | Нет | Только GROUP; повтор запрещён |
| Удалить MEMBER | Да | Да | Нет | Только GROUP |
| Удалить ADMIN | Да | Нет | Нет | Только OWNER |
| Удалить OWNER | Нет | Нет | Нет | Запрещено в MVP |
| Назначить MEMBER роль ADMIN | Да | Нет | Нет | Только OWNER |
| Снять ADMIN до MEMBER | Да | Нет | Нет | Только OWNER |
| Назначить роль OWNER через API | Нет | Нет | Нет | Смена владельца не входит в MVP |
| Менять состав DIRECT | Нет | Нет | Нет | Состав фиксирован |
| Переименовывать DIRECT | Нет | Нет | Нет | Имя показывает собеседника |
| Читать или искать в чужом чате | Нет | Нет | Нет | Отсутствует строка `chat_members` |
| Отправлять в чужой чат | Нет | Нет | Нет | Проверка выполняется до записи |

## Принцип минимальных привилегий

Модель выдаёт только права, необходимые роли:

1. MEMBER общается, но не меняет состав или роли.
2. ADMIN решает повседневные задачи группы, но не управляет другими администраторами и владельцем.
3. OWNER выполняет редкие чувствительные операции с ролями.
4. Членство всегда проверяется сервером. Скрытая кнопка в React - только удобство, не механизм безопасности.
5. Права ограничены одним чатом; доступ к другим группам не наследуется.

## Серверное применение правил

- `requireMembership(chatId, userId)` возвращает членство или HTTP 403.
- `requireGroup(chat)` запрещает изменение DIRECT-чата.
- `requireManager(member)` допускает OWNER и ADMIN для переименования/добавления.
- `changeRole` отдельно требует `OWNER` и принимает только `ADMIN` либо `MEMBER`.
- `removeMember` запрещает удаление OWNER; ADMIN может удалить только MEMBER.

После удаления пользователя из группы сервер:

1. удаляет строку `chat_members`;
2. исключает все его активные сокеты из `chat:<chatId>`;
3. отправляет в `user:<userId>` событие `chat_access_revoked`;
4. последующие REST-запросы истории и поиска получают HTTP 403;
5. `join_chat` и `send_message` получают Socket.IO ack `{ ok: false, error }` с той же причиной отказа.

## Границы MVP

- Нет глобального суперпользователя PulseChat.
- Нет передачи владения, добровольного выхода OWNER и нескольких OWNER.
- Нет отдельных разрешений на чтение и запись: любой участник может и читать, и отправлять.
- Модерация содержимого, блокировка пользователя и временные роли не реализованы.
